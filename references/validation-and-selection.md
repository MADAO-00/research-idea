# 验证机制并筛选候选

在已有候选 idea，需要判断可行性、设计实验或确定优先级时阅读。交付实验设计时，清楚区分已经完成的测量与尚未执行的计划。

## 先做最有判别力的实验

围绕最大不确定性选择实验，而不是默认完整训练。可考虑已有结果的分层复核、受控扰动、小规模消融、简化设置或信息可用性检查。说明该实验能区分哪些解释，不能排除哪些因素。

每个实验约定：

- 被检验的假设及主要替代解释；
- 固定条件、干预变量、观测量和独立评价单位；
- 各解释预测的不同结果；
- 支持、否定或仍不确定时的后续动作；
- 资源、所需材料及是否存在执行限制。

诊断可以使用理想信息探索瓶颈，但要标明它不证明可部署性。低成本实验支持假设后，再设计更完整的验证。

## 拆分适配与方法贡献

| 组别 | 内容 | 能回答的问题 |
|---|---|---|
| A | 原始、可信的 baseline | 当前问题与性能基准 |
| A′ | 仅建立所需表示或结构条件 | 适配本身的效果 |
| A′＋B | 适配后加入候选机制 | B 在适配条件下的增量效果 |
| A＋B（可合理实现时） | 不采用该适配直接引入 B | 适配是否改变 B 的效果 |
| A′＋简单替代（有意义时） | 相近资源或更简单的处理 | 复杂机制是否优于常规修补 |

A′ 与 A′＋B 的差异不单独证明预想因果机制。根据主张加入中间量、条件扰动或核心机制消融；不要求所有任务机械执行所有组别。

当四组 A、A′、A＋B、A′＋B 均可合理构造时，可进一步比较 B 在有无适配条件下的增量差异。缺少合理定义的组别时说明原因，不造一个明显无效的对照来制造优势。

## 同时检查目标问题、总体收益与代价

预先选择与主张相匹配的评价：

| 层面 | 示例 |
|---|---|
| 机制 | 信息保留、对齐误差、关键条件满足程度、干预响应 |
| 目标失败 | 特定条件下的错误率、严重程度、稳定性 |
| 整体表现 | 总指标、其他子群体、独立数据与新条件 |
| 成本 | 参数、训练和推理计算、延迟、额外标注或传感器 |

中间量是代理指标时说明它为何关联主张，不能默认代理改善就证明真实任务改善。若局部改善伴随其他场景退化，报告适用范围和权衡；不要求所有研究都声称无条件总体提升。

## 比较与数据使用

尽量控制预处理、数据、训练和调参投入、实现质量及评价协议；无法完全等预算时，报告差异和合理的预算对照，避免把额外算力收益归因于机制。

按任务独立性选择评价单位。连续帧、同一受试者或同一采集批次可能相关，不把它们当作大量独立重复。按不确定性与成本选择重复次数，报告波动或适当区间，不预设固定种子数即可证明稳定。

用于发现 bad case 或反复调整方案的数据已经参与决策，应与独立确认数据区分。根据任务按主体、场景、时间或采集批次划分，防止近重复泄漏。选择指标与成功标准后记录，避免看完最终结果再改为有利口径。

用户只有一份数据或资源不足时，明确哪些结论只能视为探索性，以及需要什么独立证据；不把这一限制变成停止所有有用工作的理由。

## 选择优先候选

综合以下维度给出有理由的排序，不把它们机械相加为精确分数：

| 维度 | 判断依据 |
|---|---|
| 问题价值 | 影响范围、严重程度、实际或科学意义 |
| 机制依据 | 现象是否稳定，解释是否有直接支持 |
| 研究增量 | 与最接近工作的差异及检索边界 |
| 可行性 | 数据、信息、算力、实现和评价条件 |
| 验证效率 | 关键假设能否低成本判别，失败是否仍有信息 |
| 复杂度与代价 | 是否存在更简单的等效解决方式 |

区分“有趣的方向”“可检验假设”“已有支持的候选”和“充分验证的结果”。这些状态取决于实际证据，不由方案文字完整程度决定。

可采用“优先验证、补充诊断后再定、暂缓”作为行动建议。证据不足允许暂不排名；用户要求探索时，提供有边界的候选，不只列出缺失材料。

## 继续、修改或放弃

提前写下会改变决策的结果，例如：

- 问题在可靠评估中不复现：回到问题发现，而不是继续加模块。
- 常规修正已经解决失败：报告修正，重新评估是否还有研究缺口。
- 必需信息无法获得或代价超出约束：考虑替代机制或暂缓。
- 目标指标改善但机制预测失败：保留观察结果，修正贡献解释。
- 多个候选效果接近：优先考察简单性、成本和可验证性，不凭微小差异声称胜出。

研究贡献可以是新方法，也可以是新的失效规律、机制证据、数据或评价设计、适用边界。跨领域组合本身不足以证明贡献，需要说明新增知识及相应证据。

本阶段结束时，给出最值得先做的一项实验、预期资源和结果分支。若执行已获授权，按当前任务范围继续；否则交付具体可运行的设计，而非声称实验完成。
