# 从线索到研究问题

在任务尚未具体化，或需要分析论文、数据和失败记录时阅读。目标是形成带证据边界的问题与可区分的解释。

## 四类入口

### Related Work：提取假设及其边界

对与任务直接相关的方法，记录：问题、核心机制、依赖条件、报告的局限、实验证据、原始来源。阅读作者的分类，同时检查是否遗漏竞争路线，或把不同条件下的方法放在一起比较。

把“泛化差”“复杂场景不稳定”等描述细化为具体的分布变化、信息缺失或运行条件。区分：作者承认的局限、作者对他人的概括、实验观察到的失败、研究者新提出的推测。

发现重复局限后，追查原始依据和后续工作，包括不同领域使用的不同术语。长期未解决可能源于信息不足、成本过高或问题设定，不自动意味着难度适中。

如果用户要求完整阅读一个论文集合，按其范围覆盖相关材料及必要的基础方法，不只读取标题最接近的文章；仍需声明没有读到或无法获取的部分。

### 失败样本：先分组，再解释

先确认 baseline 的实现、预处理、训练状态与评估口径足以支撑比较。区分实现错误、数据缺陷、配置失配、统计波动与研究问题；修复明显错误可以是必要前置，但修复本身不能自动包装成方法创新。

记录每类失败的触发条件、数量与分母、严重程度、复现情况，以及相近的成功样本。按与任务有关的尺度、时长、遮挡、来源、速度、难度或任务阶段分组。不要只保留支持某一解释的案例。

将表现较差的子群与成功群比较时，检查多个因素是否同时变化。失败组小、分组是事后发现或波动较大时，降低结论强度。不要仅凭几张可视化就给出普遍的因果解释。

### 数据特点：检查信息与模型假设是否匹配

关注与任务可能相关的结构：多尺度、周期、长尾、关键事件、缺失、异步、噪声、非平稳性、来源差异。对每个特点建立并验证：

> 数据结构 X → 当前方法依赖假设 Y → 在条件 S 下不匹配 → 产生错误 E。

询问信号是否与任务有关、是否已被 baseline 利用、实际运行时是否可观测、在新数据中是否仍成立。训练时可获得的未来信息、理想标签或真实状态不能默认作为部署输入。

### 跨领域机制：作为候选解，不跳过问题确认

如果先被某篇外领域方法启发，先写它对应的本领域问题与可观测证据。尚无证据时，把方案标为探索假设，并设计存在性诊断；不要倒推一段没有依据的失败故事。

## 1a—2b—A1 循环

| 步骤 | 操作 | 产物 |
|---|---|---|
| 1a 观察 | 描述实际发生的行为，定位原始材料 | 事实与测量口径 |
| 1b 归类 | 按条件分组，比较相近成功与失败 | 稳定失效模式或尚不稳定的线索 |
| 2a 追问 | 对关键环节提出替代解释 | 竞争性机制假设 |
| 2b 因果链 | 连接输入、表示、运算、决策和结果 | 每条关系的依据或待验标记 |
| A1 新发现 | 检查新证据支持、反驳或改变了什么 | 下一轮最有信息量的问题 |

保留三种陈述：

- **观察：** 在怎样的采样和评价条件下看到了什么。
- **假设：** 哪个机制可能产生该现象，还有哪些解释。
- **检验：** 干预什么、观察什么，不同解释分别预测什么。

不要用重复“为什么”代替实验。无法再区分解释时，应找缺失的观测或干预；没有明确新增信息时停止继续写长因果链。

## 例：快速运动时误差增大

以下是说明诊断方式的假设案例，不代表任何具体系统的实测结论。

| 候选解释 | 区分性诊断 | 应观察的变化 |
|---|---|---|
| 输入与标签时间错位 | 在可信时间戳或受控数据上改变对齐偏移 | 误差随偏移出现可预测的变化 |
| 动态建模能力不足 | 在对齐可靠、覆盖可比的样本上改变运动速度 | 速度相关误差在排除对齐问题后仍存在 |
| 训练覆盖不足 | 控制其他差异，改变相应样本覆盖 | 对新增覆盖的响应符合预期 |
| 标签噪声更大 | 使用独立复核或更可靠的测量 | 标签修正对误差解释有实质影响 |

单次诊断可能无法排除所有混杂，明确剩余解释。如果一个简单的数据对齐修正已解决问题，应如实报告，再判断是否还存在值得研究的机制缺口。

## 从问题筛出可研究的候选

对每个候选确认：问题是否重要；证据是否可复核；哪些关系可以干预；现有方法是否已充分处理；可用资源能否支持关键验证。

只有宽泛方向时，输出“问题候选—为何值得查—需要什么证据—先做哪个诊断”。材料不足时不编造 bad case、数据特征、运行结果或论文共识。

本阶段的合格产物是能被下一步检索或实验使用的问题：

> 在 S 条件下，baseline A 出现 E。已有证据为 O；解释 M 与 M_alt 尚待区分。通过干预 I 观察 Z，可以缩小解释范围。
