# 机制检索与跨领域适配

在具体问题需要外部方案、核查相关工作或评估跨领域迁移时阅读。A 是目标任务与 baseline，B 是候选机制来源，C 是可选的已有迁移案例。

## 检索前：描述问题及约束

把任务词转成机制词，同时保留信息可用性、在线或离线、时空结构、监督、计算和延迟约束。避免只检索模型名，也避免把问题泛化成毫无约束的“如何提高性能”。

| 任务描述 | 可能的机制检索轴 |
|---|---|
| 长序列性能下降 | 远距离信息保留、有限容量、误差累积 |
| 多传感器融合不稳定 | 异步观测、可靠性变化、相关噪声 |
| 密集小目标漏检 | 局部弱信号、压缩损失、目标间干扰 |
| 训练好而部署差 | 分布变化、信息不可用、闭环反馈、时序延迟 |

这些只是检索候选，不是对某任务的根因判断。为关键概念生成同义词与其他学科的术语，同时搜索负面结果、限制、替代解释和更简单的方案。

## 检索与原文核查

按问题需要查三类材料：A 中最近或最接近的解决方案、B 中的原始机制、C 中的迁移与失败案例。不强制找到某个数量或领域组合。

优先使用原始论文、作者官方项目与可定位的代码。综述和搜索摘要可帮助发现线索，但方法细节、实验结果与适用范围回到原始材料核对。预印本标明状态；第三方复现与作者实现分别记录。

记录实际执行的检索日期、关键词、范围、入选与排除理由。每个关键来源记录标题、作者、年份或版本、直接链接、章节或页表定位，以及实际读了摘要、方法、实验还是全文。网页与本地文件都应保留可复核位置。

作者报告、自己的解释和自己的实验分开书写。没有访问原文就不声称已核实；不能获取的方法细节列入缺口。未检索时不要生成虚构的检索日志或引用。

新颖性表述使用边界：例如“在本次覆盖的来源和术语范围内，尚未找到满足这些约束的方案”。这不构成“全球首次”的证明。

## 拆解 B 为什么有效

为候选 B 回答：原始缺陷是什么、真正起作用的运算或结构是什么、哪项证据支持该解释、依赖什么条件。

| 条件 | 需要核查的问题 |
|---|---|
| 输入 | 是否需要时间、可靠性、多视角、额外传感器或特定标签？ |
| 表示 | 必要信息是否仍可区分，还是已在前序处理丢失？ |
| 数据 | 是否依赖分布、样本量、独立性、平稳性或噪声模型？ |
| 训练 | 是否依赖特殊监督、损失、阶段或优化条件？ |
| 运行 | 计算、延迟、内存和观测频率是否满足任务？ |

区分可能必要的条件、有帮助的条件与实现选择。作者采用了某种结构不代表它不可替代；某项消融也只支持被测试范围内的判断。没有条件消融时，明确它仍是机制解释或推测。

## C 提供什么证据

找到迁移案例后，比较 B 与 C 的输入、表示、连接、目标、监督、输出和运行约束。记录保留的机制与新增适配，以及这些变化是否被分别评估。

C 只提供最终指标时，不能确认某个适配必不可少。没有 C 时继续分析可行性，将未知条件变成优先验证项；不要把缺少迁移案例当作新颖性的充分证据。

## 为 A 建立生效条件

建立一张条件表，逐项写“已具备、可通过适配建立、尚待核实或与约束冲突”，并说明依据及成本。先判断机制是否能成立，再设计接口。

可选路线包括改造 A、改造 B 或共同调整。选择满足关键条件、改动较小且容易做对照的方案；不预设必须保留 B 的原始结构。张量形状匹配只证明接口兼容，不证明信息语义和机制相容。

若机制需要的信息无法获得，明确提出可检验的替代估计或转向其他候选；不能默认完美状态、未来信息或额外硬件已经可用。数据、目标函数和系统流程也可以成为适配对象，不强制增加模块。

## 迁移输出

对重点候选交付紧凑的 A/B/C 对照：

| 项目 | A 的实际状态 | B 的要求与依据 | C 的经验（若有） | 拟议适配与缺口 |
|---|---|---|---|---|
| 问题与机制 | 填入实际材料 | 填入核实结论 | 填入核实案例 | 标注推测 |
| 关键生效条件 | 说明具备程度 | 区分证据与解释 | 保留或改变了什么 | 可测量的条件 |
| 训练与部署约束 | 用户约束 | 方法依赖 | 案例适用范围 | 成本与冲突 |

最后写成机制假设：

> A 在 S 条件下因 M 出现 E。适配 I 建立条件 C，使 B 能改变 M。若成立，中间量 Z 与目标错误 E 应发生预期变化；若关键变化未出现，则修正机制解释或放弃该方案。

完整验证与筛选转到 [validation-and-selection.md](validation-and-selection.md)。
